# Decisions

Any deviation from KIRO_PLAN.md is recorded here with the reason.

| # | Area | Original plan | What we did instead | Reason | Date |
|---|---|---|---|---|---|
| 1 | MCP SDK package name | `@modelcontextprotocol/sdk` v2 | `@modelcontextprotocol/server` v2 + `@modelcontextprotocol/client` v2 | The MCP TypeScript SDK v2 ships as separate `@modelcontextprotocol/server` and `@modelcontextprotocol/client` packages (the monolithic `sdk` package is v1). mcp-handler 2.x requires the split packages. | 2026-10-09 |
| 2 | Protocol tests use raw fetch | Tests send plain JSON POST and parse JSON response | Tests send `Accept: application/json, text/event-stream` and parse SSE `data:` line | mcp-handler 2.x implements full Streamable HTTP: it rejects requests missing the Accept header with HTTP 406, and returns responses as SSE even for single-turn calls. Documented in friction-log. | 2026-10-09 |
| 3 | AWS region | us-east-1 per tech.md | us-east-2 for deployment | An SCP (`p-bobb142o`) on the deploying AWS account denies CloudFormation, Lambda, and most services in us-east-1 and us-west-2. us-east-2 passes all service checks. Region can be overridden via `CDK_DEFAULT_REGION` env var. | 2026-10-09 |

| 4 | Store layout | One store interface with DynamoDB and in-memory versions | A small `ItemStore` interface (get, query, all-or-nothing `transact` with conditions) with two backends, and one `Repo` class holding all game operations on top of it | The game logic, conditions, and transactions are written once and tested once against the in-memory backend. The DynamoDB backend is a thin translation to GetItem / Query / TransactWriteItems. | 2026-10-08 |
| 5 | Item `type` attribute | Items identified by SK prefix only | Every item also carries a `type` attribute (`household`, `player`, `pack`, `question`, ...) | DynamoDB filter expressions cannot reference key attributes, so "packs but not pack questions" needs a non-key attribute to filter on. | 2026-10-08 |
| 6 | get_household reads | One query on `PK = HH#<id>` with a filter | Five small parallel requests (META, PLAYER#, open CHORE#, PACK# packs, unseen NEWS#) | A filtered query still reads every ledger entry and closed round, so its cost grows with history. Parallel prefix queries stay constant and take one round trip of wall time. The open round and a last-round summary live on the META item. | 2026-10-08 |
| 7 | Idempotency records | Not in the data model | `IDEMP#<key>` items under the household, written in the same transaction as the round | Makes R3.5 hold even for two concurrent retries: the second transaction fails its condition and returns the stored result. | 2026-10-08 |
| 8 | start_round modes | "hosted or riddle" | `hosted`, `riddle`, and `family` | `family` opens a round with a stake (and tiebreak players) where the family asks the question, so "let's play for the garbage" works whether or not the host asks. | 2026-10-08 |
| 9 | Parent phrase hash | Salted hash | scrypt (Node `crypto.scryptSync`, 32 bytes, per-household salt), compared with `timingSafeEqual` | A slow hash makes an offline guess against a leaked item expensive. Still well inside the latency budget. | 2026-10-08 |
| 10 | Table removal policy | (not specified) | `RemovalPolicy.DESTROY` | R12.4: `pnpm infra:destroy` must remove every resource. | 2026-10-08 |
| 11 | Development tokens on AWS | Dev token in local mode only | The deployed server also seeds `dev-token-demo` (demo family) and `dev-token-bench` (a copy used only by the latency test) until account linking lands in milestone 5 | The simulator and the latency test need a household on the deployed URL before Cognito exists. The bench household keeps 450 latency calls from touching the demo scores. | 2026-10-08 |
| 12 | Where the simulator's MCP client runs | (not specified) | In the browser. A thin `/api/model` route calls Bedrock with the MCP tool list and returns either speech or tool calls; the browser runs the tool calls through its MCP client and loops | The protocol panel shows the real JSON-RPC traffic the browser sends, "New session" really keeps nothing, and the model route stays stateless. | 2026-10-08 |
| 13 | Polly voice | Neural voice | Standard engine, voice Joanna (`POLLY_ENGINE`, `POLLY_VOICE_ID` override) | Polly in us-east-2 offers only the standard engine, and the account's SCP blocks Polly in us-east-1 and us-west-2. If Polly is unavailable the browser's own voice is used. | 2026-10-08 |
| 14 | MOCK_MODEL turns | "Recorded model turns from the replay scripts" | Host turns are written by hand into each replay line (tool calls with `{{tool.field}}` templates, and what to say). In mock mode, live speech or typing plays the next line of the selected script ("read-along") | Recorded turns would carry ids (roundIds, random pack questions) that don't match a fresh run. Written turns are deterministic, still call the real MCP server, and let a person play the scripts by voice with no model. | 2026-10-08 |
| 15 | Local ports | (not specified) | MCP server on 4787, simulator on 3000 | 3001 and 8787 were already in use on the development machine. | 2026-10-08 |
| 16 | Simulator model | Nova 2 Lite on Bedrock | Still Nova 2 Lite, but called through the Vercel AI Gateway (`amazon/nova-2-lite`) by default. Direct Bedrock stays in the code behind `MODEL_PROVIDER=bedrock`. | The account's Bedrock daily token quota for every Nova model is 0 and marked "not adjustable", so every direct call fails with ThrottlingException. Other entrants with new accounts hit the same block, and the organizers can't escalate it (Devpost forum topics 45416 and 45474). The gateway serves the same model, so the prompt and tools are unchanged. The Bedrock route is verified up to Bedrock's quota check. | 2026-10-08 |
| 17 | pnpm layout | Default pnpm (isolated) `node_modules` | `node-linker=hoisted` in `.npmrc` | Amplify Hosting requires a hoisted linker for pnpm workspace apps. All tests, the Next.js build, and the Lambda bundle were re-verified with it. | 2026-10-08 |
| 18 | Simulator AWS access on Amplify | (not specified) | An Amplify SSR compute role (`hey-trivi-simulator-compute`, in CDK) allowing only Nova 2 Lite invocation and Polly speech | No AWS keys in environment variables. The role is attached to the Amplify app after it is created from the GitHub repo. | 2026-10-08 |
| 19 | Parent page data access | Parent page in the Next.js app, reading the store | The parent page's API lives on the MCP server at `/parent/*` (same Hono app, same store). The Next.js app only signs the parent in and forwards calls with their access token | One place writes household data, so the game and the parent page can't drift, and local mode works: the in-memory store lives in the MCP server process, so a Next.js-side store would be a different, empty copy. The Amplify compute role needs no DynamoDB access. | 2026-10-09 |
| 20 | Sign-in without AWS | Cognito only | With no `COGNITO_DOMAIN` set, the parent page offers a local dev sign-in ("Sign in as the demo family" / "Start a new family") using `dev-user-<name>` tokens. The MCP server accepts these only in local mode (no `DYNAMODB_TABLE`) | A fresh clone must run with no AWS account (R12.1), including signup and the parent page. Deployed servers never accept them. | 2026-10-09 |
| 21 | Simulator account linking (6.5) | A "Link account" button that runs the OAuth flow as the simulator's client | The simulator runs in the same app as the parent page, so it uses the signed-in parent's Cognito access token when there is one, and the demo token otherwise. The header shows which family is playing | Same result for checkpoint 5 (sign up, then play as that family) with no second OAuth client. The MCP server validates that token exactly as it would one from Alexa+. | 2026-10-09 |
| 22 | Token check | Validate signature, issuer, expiry, audience | `aws-jwt-verify` checks Cognito access tokens (signature against the pool's JWKS, issuer, expiry, `token_use: access`, and `client_id` against `COGNITO_CLIENT_IDS`). Cognito access tokens carry no `aud`, so the client id is the audience check | Official AWS library; caches the JWKS across warm Lambda calls. | 2026-10-09 |
